# Инкрементальный план миграции (7 этапов)

|Этап|Срок|Содержание|Результат|
|-|-|-|-|
|**1. Data discovery**|Месяц 1|Инвентаризация систем, таблиц, потоков, владельцев данных. Построение As-Is карты данных.|Реестр данных, карта потоков, назначены Data Owners.|
|**2. MDM Customer Hub (пилот)**|Месяцы 1–3|Внедрение MDM для «Участвующей стороны». Настройка дедупликации и слияния записей из FU CRM и RB CRM. Создание "Золотой записи".|Единый клиентский идентификатор. MDM синхронизирует клиентов с обеими CRM.|
|**3. Единое DWH (промежуточное)**|Месяцы 2–4|Развёртывание DWH на PostgreSQL. Настройка ETL из FU Core, RB Core, FU Cards, RB Cards, FU Loans, RB Loans. Построение первой управленческой отчётности.|Единая отчётность по клиентам, счетам, продуктам и операциям.|
|**4. Integration Layer + Kafka**|Месяцы 4–6|Внедрение Integration Layer и Kafka для событийного обмена. Замена point-to-point интеграций RetailBank. Настройка CDC из АБС и CRM.|Централизованный обмен данными. Снижение нагрузки на OLTP.|
|**5. Data Lakehouse (история и ML)**|Месяцы 6–9|Развёртывание Lakehouse (Iceberg + Trino). Загрузка исторических архивов (карточные операции, логи обращений). Настройка потоковой обработки событий.|Единое хранилище сырых и исторических данных. Поддержка ML и антифрода.|
|**6. Консолидация АБС и CRM**|Месяцы 9–11|Постепенный перенос счетов, карт, кредитов, договоров из legacy RB Core и RB CRM в целевые системы. Переключение потоков.|Вывод legacy RB Core и RB CRM из эксплуатации. Единая АБС и CRM.|
|**7. Финальная сверка и DataHub**|Месяц 12|Полная сверка финансовых данных. Внедрение DataHub (каталог, lineage). Обучение пользователей. Подготовка к отключению оставшихся legacy-систем.|Достижение целевого состояния. Все критерии завершения выполнены.|
