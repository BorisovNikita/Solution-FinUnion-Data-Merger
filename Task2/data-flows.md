## Контекстная диаграмма потоков данных (DFD Level 0)

### Ключевые потоки и операции

1. **CRM FinUnion / CRM RetailBank → MDM** — `Create`, `Update`, `Delete` данных об «Участвующей стороне». Обеспечивает дедупликацию и создание золотой записи.
2. **MDM → CRM FinUnion / CRM RetailBank** — `Read` и `Enrich` золотой записью. Возвращает единый клиентский идентификатор во все CRM.
3. **Core Banking, Card Processing, Loan System (FU и RB) → Integration Layer** — `Read` (извлечение) операционных данных (счета, карты, кредиты, транзакции, платежи).
4. **Integration Layer → DWH** — `Validate` и `Create`/`Update`. Проверка качества и загрузка нормализованных данных в хранилище.
5. **MDM → DWH** — `Enrich` клиентским профилем. Обогащение аналитических данных для единой отчётности.
6. **DWH → BI** — `Aggregate` и `Read`. Расчёт витрин и выдача данных для управленческой аналитики.
7. **DWH → Регулятор** — `Read` (выгрузка отчётности). Показан как внешний потребитель.
8. **IL, MDM, DWH → DataHub** — `Create`/`Update` метаданных. Обеспечивает трассируемость (lineage) и каталогизацию.

### Ключевые архитектурные решения

* **Промежуточное состояние:** используются существующие As-Is системы без полной замены. Добавлены только MDM Customer Hub, Integration Layer, DWH (как единая точка сборки), BI и DataHub.
* **Разделение OLTP и OLAP:** операционные системы отдают данные через Integration Layer в DWH, не испытывая аналитической нагрузки.
* **Все требуемые операции отражены:** `Create`, `Read`, `Update`, `Delete`, `Enrich`, `Validate`, `Aggregate`.
* **Регуляторная отчётность** показана как поток из DWH к внешнему потребителю (Регулятор).
