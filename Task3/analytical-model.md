# Аналитическая модель данных

Для аналитической области **«Анализ транзакций и операций»** выбрана схема **«Звезда» (Star Schema)**. Она оптимальна для OLAP-нагрузки, так как обеспечивает высокую скорость агрегации и простоту понимания для BI-инструментов.

## Структура модели

|Тип таблицы|Название таблицы|Описание|
|-|-|-|
|**Fact**|`fact\_transactions`|Факты транзакций (сумма, количество, комиссия).|
|**Dimension**|`dim\_counterparty`|Измерение клиента (Участвующая сторона: ФИО, сегмент, регион).|
|**Dimension**|`dim\_account`|Измерение счета (тип счета, валюта, статус).|
|**Dimension**|`dim\_card`|Измерение карты (тип карты, платежная система).|
|**Dimension**|`dim\_date`|Измерение даты (день, месяц, квартал, год).|
|**Dimension**|`dim\_department`|Измерение департамента/филиала (регион, код подразделения).|

## Почему выбрана схема «Звезда»?

1. **Производительность:** Денормализованная структура (одна факт-таблица и связанные измерения) минимизирует количество JOIN-ов, что критично для быстрых OLAP-запросов в BI.
2. **Простота:** Бизнес-пользователи и аналитики легко понимают структуру «звезды», что ускоряет разработку дашбордов.
3. **Масштабируемость:** Легко добавлять новые измерения (например, `dim\_product`) без изменения факт-таблицы.
4. **Подходит для DWH:** В PostgreSQL схема «звезда» позволяет эффективно использовать индексы и партиционирование для больших объемов транзакций.
