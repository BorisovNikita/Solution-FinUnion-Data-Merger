# Образ целевого результата (через 12 месяцев)

|Вопрос|Что должно измениться|
|-|-|
|**Какие системы остаются**|Единая АБС (Core Banking) — целевая, объединяющая FU Core и RB Core. Единая CRM. Карточный процессинг (целевой, объединённый). Кредитная система (целевая). MDM Customer Hub. Integration Layer (ESB + Kafka). DWH (PostgreSQL/MPP). Data Lakehouse (Iceberg + Trino). BI. Airflow. DataHub.|
|**Какие системы выводятся из эксплуатации**|Legacy FU Core и RB Core (после миграции в единую АБС). Legacy FU CRM и RB CRM (после консолидации или перехода на единую CRM). Дублирующие DWH (FU DWH и RB DWH заменяются единым DWH). Point-to-point интеграции RetailBank заменяются Integration Layer. Частично — legacy карточные и кредитные системы (после слияния в целевые).|
|**Какие данные мигрируются**|Все ключевые сущности: Участвующая сторона (клиенты), Счета, Карты, Кредиты, Договоры, Транзакции, Платежные документы, Обращения, Продукты, Департаменты, Сотрудники. Исторические данные (архивы) — в Data Lakehouse. Актуальные (золотые) записи — в MDM и целевую АБС.|
|**Какие потоки переключаются**|Потоки клиентских данных: из обеих CRM в MDM (CDC). Потоки операционных данных: из целевой АБС в DWH и Lakehouse (через Kafka/CDC и Airflow). Потоки отчётности: из DWH в BI и Регулятор. Потоки метаданных: из всех систем в DataHub.|
|**Критерии завершения перехода**|1. Единый профиль клиента доступен в MDM и синхронизирован с CRM. 2. Управленческая и регуляторная отчётность строится из единого DWH. 3. Legacy RB Core и RB CRM выведены из эксплуатации. 4. Все критические потоки данных работают через Integration Layer и Kafka. 5. DataHub содержит актуальный lineage по ключевым сущностям. 6. Проведена сверка финансовых данных (счета, транзакции) — расхождений нет.|
