# Проблемные зависимости и риски

|Проблема|Последствие|Меры минимизации|
|-|-|-|
|**Разные идентификаторы клиента** (Участвующей стороны) в FU CRM и RB CRM|Невозможно построить единый профиль клиента. Дублирование обращений и ошибки в отчетности.|Внедрение MDM Customer Hub с алгоритмами нечеткого сопоставления (Fuzzy Matching) уже на 3-м месяце.|
|**Несинхронизированные статусы счетов** (например, один и тот же счет в FU Core и RB Core имеет разные статусы: «Активен» vs «Заблокирован»)|Ошибки в расчетах доступных средств, сбои в обслуживании клиентов, регуляторные риски.|Настройка CDC-потоков из АБС в DWH с ежедневной сверкой (Reconciliation) и алертингом при расхождениях.|
|**Разные тарифы и условия по продуктам**|Неверные расчеты ставок, ошибки в продажах, жалобы клиентов, некорректная управленческая отчетность.|Создание единого каталога продуктов в MDM с версионностью (SCD2). Все системы (CRM, АБС) должны читать данные из MDM.|
|**Отсутствие связей «Карта — Счет»** в некоторых legacy-системах|Невозможно корректно агрегировать балансы по клиенту и продукту.|Обязательная валидация связей на уровне Integration Layer перед загрузкой в DWH.|
|**Задержка (Latency) при синхронизации MDM с CRM**|Менеджеры видят устаревшие данные, что приводит к ошибкам в обслуживании (например, предлагают неподходящий продукт).|Установка SLA (не более 5 минут) для Near real-time обмена. Мониторинг задержек через Prometheus.|
|**Отсутствие Data Lineage (трассируемости)**|Невозможно быстро найти источник ошибки в отчетности (например, при сбое регуляторной отчетности).|Внедрение DataHub/Каталога данных на 3-м месяце для автоматического сбора метаданных из ETL-пайплайнов.|
