# Целевая архитектура данных (To-Be, 12 месяцев)

## Компоненты архитектуры

1. **Operational Systems (OLTP):**

   * Единая АБС (Core Banking), CRM, Карточный процессинг, Кредитная система.
   * Обеспечивают транзакционную целостность (ACID) и первичный сбор данных.
2. **MDM (Master Data Management):**

   * Управляет золотыми записями «Участвующей стороны», «Продукта», «Департамента» и «Сотрудника».
   * Выступает единственным источником истины для клиентских и справочных данных.
3. **Integration Layer:**

   * Обеспечивает синхронный (REST/gRPC) и асинхронный обмен между системами.
   * Выполняет роль шлюза для валидации и маршрутизации.
4. **Kafka (Event Streaming):**

   * Используется для событийных потоков (CDC из АБС, логи обращений, транзакции в реальном времени).
   * Позволяет снять нагрузку с интеграционной шины и обеспечить Near Real-Time обработку.
5. **DWH (Корпоративное хранилище):**

   * Построено на PostgreSQL (для промежуточного состояния) / специализированной MPP-СУБД (для целевого).
   * Хранит нормализованные и агрегированные данные для регламентированной и управленческой отчетности.
6. **Data Lakehouse:**

   * Построен на Apache Iceberg (формат таблиц) и Trino (движок запросов).
   * Хранит сырые (raw) исторические данные, события, архивы и данные для ML.
7. **BI (Business Intelligence):**

   * Инструменты визуализации (дашборды, отчеты), подключаемые к DWH и Lakehouse (через Trino).
8. **Airflow (Оркестрация):**

   * Управляет batch-пайплайнами, координирует загрузку данных из OLTP в DWH и Lakehouse.
9. **DataHub (Каталог данных):**

   * Обеспечивает трассируемость (lineage), поиск по метаданным, управление владельцами данных и политиками доступа.

## Логика потоков данных

* **Операционные системы** генерируют события, которые через **Integration Layer** и **Kafka** попадают в **MDM** (для клиентов) и **Data Lakehouse** (для сырых данных).
* **MDM** синхронизирует золотые записи обратно в операционные системы и обогащает **DWH**.
* **Airflow** оркестрирует регулярные выгрузки из OLTP в **DWH** и **Lakehouse**.
* **BI** и **Регулятор** потребляют данные из **DWH** (регламентированная отчетность) и **Lakehouse** (продвинутая аналитика через Trino).
