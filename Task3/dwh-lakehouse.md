# Сравнение DWH на PostgreSQL и Data Lakehouse

## Сравнение для кейса FinUnion + RetailBank

|Характеристика|DWH на PostgreSQL|Data Lakehouse (Iceberg + Trino)|
|-|-|-|
|**Тип данных**|Структурированные, нормализованные|Сырые, полуструктурированные, архивы, события|
|**Объемы**|До нескольких ТБ (для отчетности)|Петабайты (история транзакций, логи)|
|**Стоимость хранения**|Высокая (SSD, лицензии/ресурсы)|Низкая (объектное хранилище S3)|
|**Поддержка ACID**|Полная (нативно)|Через Apache Iceberg (ACID-транзакции на озере)|
|**ML и Advanced Analytics**|Ограниченная|Полная (Spark, Python, ML-библиотеки)|
|**Скорость BI-запросов**|Высокая (для денормализованных витрин)|Средняя/Высокая (через Trino, кэширование)|

## Выбранный подход

**Гибридный:**

* **Промежуточное состояние (3 мес.):** DWH на PostgreSQL. Быстрый старт, единая точка сборки отчетности для FinUnion и RetailBank.
* **Финальное состояние (12 мес.):** DWH (PostgreSQL/MPP) для регламентированной отчетности + Data Lakehouse для истории, ML и событийных данных.

## Роль Apache Iceberg и Trino

* **Apache Iceberg:** Обеспечивает **ACID-транзакции**, версионность (time travel) и эволюцию схемы прямо на объектном хранилище (S3). Это делает Data Lakehouse надежным для финансовых данных, устраняя риск «грязных» чтений.
* **Trino:** Движок для **федеративных запросов**. Позволяет BI-инструментам обращаться к данным в Lakehouse (Iceberg) и DWH (PostgreSQL) одновременно, не перегружая данные. Обеспечивает высокую скорость OLAP-запросов.

## Распределение данных

* **Остается в DWH:** Регламентированная отчетность, агрегированные финансовые витрины, данные для ежедневного мониторинга (KPI), отчеты для Регулятора.
* **Попадает в Lakehouse:** Сырые (raw) данные из OLTP, исторические транзакции (>3 лет), логи обращений, события карточных операций, данные для ML (антифрод, скоринг).

## Ограничения выбранного подхода

1. **Сложность управления двумя средами:** Требуется экспертиза в PostgreSQL и Spark/Iceberg/Trino.
2. **Задержка данных в Lakehouse:** Микро-батчи или потоковая загрузка могут давать задержку в несколько минут, что критично для некоторых видов отчетности.
3. **Безопасность:** Необходимо обеспечить единый RBAC и маскирование ПДн как в DWH, так и в Lakehouse (Trino + Ranger).
