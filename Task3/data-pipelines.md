# Пайплайны данных

## Пайплайн 1: Простой пайплайн для DWH на PostgreSQL (промежуточное состояние, 3 месяца)

* **Источник:** CRM FinUnion, CRM RetailBank, Core Banking (FU и RB).
* **Приёмник:** DWH (PostgreSQL).
* **Тип:** Batch ETL/ELT.
* **Инструменты:** Airflow, Python-скрипты, dbt.
* **Описание:** Ежедневная выгрузка справочников клиентов, счетов и транзакций. Airflow запускает задачу в 01:00, данные валидируются (проверка дублей, форматов) и загружаются в DWH для построения единой управленческой отчетности.

## Пайплайн 2: Синхронизация мастер-данных (MDM)

* **Источник:** CRM FinUnion, CRM RetailBank.
* **Приёмник:** MDM Customer Hub.
* **Тип:** CDC (Change Data Capture), Near Real-Time.
* **Инструменты:** Debezium, Kafka, Airflow (для контроля).
* **Описание:** Захват изменений в CRM (создание, обновление клиента) и отправка событий в MDM. MDM выполняет дедупликацию (Fuzzy Matching) и формирует "золотую запись", которая затем синхронизируется обратно в CRM.

## Пайплайн 3: Обработка истории карточных операций (Big Data Scenario 1)

* **Источник данных:** Карточные процессинги (Card Processing FU и RB) — архивные выгрузки за 5 лет.
* **Характер данных:** Исторические, полуструктурированные (JSON, CSV).
* **Целевое хранилище:** Data Lakehouse (Iceberg).
* **Способ обработки:** Batch ETL (Spark).
* **Потребители:** Риск-менеджмент, антифрод, BI (через Trino).
* **Описание:** Архивные логи карточных операций выгружаются в объектное хранилище (S3), конвертируются в формат Iceberg и партиционируются по датам. Позволяет анализировать исторические паттерны мошенничества и строить скоринговые модели.

## Пайплайн 4: Поток событий клиентских каналов (Big Data Scenario 2)

* **Источник данных:** Мобильное приложение, веб-сайт, контакт-центр (логи кликов, звонки, чаты).
* **Характер данных:** Событийные, потоковые, неструктурированные (JSON, тексты).
* **Целевое хранилище:** Kafka -> Data Lakehouse (Iceberg).
* **Способ обработки:** Streaming (Kafka + Spark Streaming).
* **Потребители:** Маркетинг, UX/UI, антифрод (выявление аномалий поведения).
* **Описание:** События в реальном времени попадают в Kafka, затем стриминговым способом записываются в Lakehouse. Позволяет в реальном времени анализировать поведение клиентов и предлагать персонализированные продукты.
